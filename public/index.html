I-MAGIC 的順序

NLM I-MAGIC 示範頁的說明：用規則式的 SNOMED CT → ICD-10-CM 對照表，先看概念加病人的年齡、性別能不能決定一個有效的碼；不能就問（必填追問）。有碼了還可能有選填追問：左右側、孕期，或換成更明確的 SNOMED 概念。

#題何時問必填
1性別、年齡規則依病人資料分岔而資料未填規則需要時
2更明確的診斷概念底下有更細的概念否，可選「都不是」
3左右側ICD 碼分左右否，可選未明示
4第 7 碼損傷章（S、T）的碼是：A 初次、D 後續、S 後遺症

兩種模式

  • 離線：rules.json。把每個概念在各種條件下丟給 I-MAGIC 示範頁、記下回答整理成的。不是 NLM 官方對照檔（檔案要 UMLS 帳號）。
  • 直通：概念不在離線規則裡時，伺服器把目前的答案帶去問 I-MAGIC，回的是官方當下的結果。要能連 NLM，每題約 1 到 2 秒。

台灣查核

I-MAGIC 用美國現行版碼表；台灣自 2025-01-01 起用 2023 年版。每個結果碼查 CMS FY2023 碼表：有則附健保署查詢系統的中文名；沒有則列同一 stem 底下 2023 年版的碼，以及 CMS FY2027 轉換表寫的「此新碼之前對應的碼」。

個人練習專案。I-MAGIC 會讓問題清單上的多個概念互相精煉；這裡一次只看一個概念。

API

本機、JSON、無驗證。程式用法：丟 ID；status 為 need_info 時讀 question，把答案加成參數再呼叫，直到 done。

GET /api/map/8619003
→ {"status":"need_info","question":{"type":"sex",...},"rows":[{"code":"TBD",...}]}
GET /api/map/8619003?sex=female
→ {"status":"done","rows":[{"code":"N97.9","name":"Female infertility, unspecified","tw_valid":true,"tw_zh":"女性不孕"}]}
GET /api/map/44465007?laterality=S93.402&episode=D
GET /api/map/59621000?age=70              age 歲；或 age_days 天
GET /api/map/267036007?mode=live          mode: auto（預設）| offline | live
GET /api/search?q=ankle%20sprain          英文名稱找概念（tx.fhir.org）
GET /api/tw/E11.A                         台灣 2023 年版查核
GET /api/concepts    GET /api/health
欄位值
statusdone（1–2 碼）、multiple、need_info、no_target（有概念但無對應碼）、not_in_map（I-MAGIC 不收；附 sct.inactive 說明概念是否已停用）、unknown（離線沒有且直通關閉）
mode / releaseoffline 或 live；I-MAGIC 的 Map 版本
rows[]code、ext（第 7 碼）、name、tw_valid、tw_name、tw_zh、tw_children、tw_prev
questiontype（sex / age / refine / laterality / episode）、required、options[]
