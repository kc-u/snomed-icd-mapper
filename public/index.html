I-MAGIC 的做法：先看病人資料，不夠才問

NLM 的 I-MAGIC 示範頁說明：用規則式的 SNOMED CT → ICD-10-CM 對照表，先看概念加上病人的年齡和性別能不能決定一個有效的碼；不能就問使用者（必填追問）。就算有碼了，對照表還可能提供選填追問，例如左右側、孕期，或換成更明確的 SNOMED 概念。

1 病人資料性別、年齡。缺了而規則需要，就是必填題。
2 更明確的診斷列出這個概念底下更細的概念，有就換成那個。選填。
3 左右側ICD 碼分左右的才問。選填，不知道就「未明示」。
4 第 7 碼損傷章的碼一定要：A 初次、D 後續、S 後遺症。必填。
5 出碼剩一個碼，或兩個都要填的碼。

兩種模式

  • 離線：用 rules.json。裡面的碼是把每個概念在各種條件下丟給 I-MAGIC 示範頁、把回答記下來整理成的，不是 NLM 官方對照檔（檔案要 UMLS 帳號）。目前只有少數概念。
  • 直通：概念不在離線規則裡時，伺服器現場把你的答案帶去問 I-MAGIC，回的就是官方當下的結果。要能連到 NLM，每題約 1 到 2 秒。

台灣查核

I-MAGIC 用美國現行版碼表；台灣自 2025-01-01 起用 2023 年版。每個結果碼都查 CMS 2023 年版碼表：有就附健保署查詢系統的中文名；沒有就列同一 stem 底下 2023 年版有的碼，以及 CMS 轉換表寫的「這個新碼之前對應哪個碼」。

注意這是個人練習專案。I-MAGIC 一次會看問題清單上的所有概念互相精煉，這裡一次只看一個概念。

API

伺服器在本機，回 JSON，沒有驗證。agent 的用法：丟 ID 進來，status 是 need_info 就看 question，把答案加成參數再呼叫一次，直到 done。

GET /api/map/8619003 → {"status":"need_info","question":{"type":"sex",...},"rows":[{"code":"TBD",...}]} GET /api/map/8619003?sex=female → {"status":"done","rows":[{"code":"N97.9","ext":"","name":"Female infertility, unspecified","tw_valid":true,"tw_zh":"女性不孕"}]} GET /api/map/44465007?laterality=S93.402&episode=D GET /api/map/59621000?age=70 age 歲，或 age_days 天 GET /api/map/267036007?mode=live mode: auto（預設）| offline | live GET /api/search?q=ankle%20sprain 名稱找概念（tx.fhir.org） GET /api/tw/E11.A 台灣 2023 年版查核 GET /api/concepts · /api/health

回傳欄位

  • status：done（1–2 個碼）、multiple、need_info、not_in_map（I-MAGIC 不收）、unknown（離線沒有且直通關閉）
  • mode：offline 或 live；release：I-MAGIC 的 Map 版本
  • rows[]：code、ext（第 7 碼）、name、tw_valid、tw_zh、tw_children、tw_prev
  • question：type（sex / age / refine / laterality / episode）、required、options[]
